# Family Database v2

家族向けの予定・給食・掃除・買い物Dashboard。静的なGitHub Pages + Supabaseで動作します。

- 公開ページ: https://hideboshi06.github.io/family-database-v2/
- GitHub: `hideboshi06/family-database-v2`（個人用アカウント）
- Supabaseプロジェクト: `Family Database`（個人用 `hideboshi`）
- データテーブル: `daily`、`cleaning`、`shopping`
- アクセス管理: `family_members` + Supabase Auth Google OAuth + RLS

## 現在実装済み

- SafariでのGoogleログイン、許可ユーザーの判定、ログアウト（iPadのホーム画面起動・アプリ内ブラウザではGoogle認証に制約があるためSafari利用を推奨）
- 今日の天気・予定・給食・ゴミ、明日の準備（天気・給食）、直近9日間の予定
- 下部の「スケジュール」タブから確認、ページ末尾の「月間編集」で月間予定の入力・訂正・まとめて保存
- 月間給食の入力・貼り付け・訂正・まとめて保存
- 日別予定編集
- 掃除の一覧と「完了」操作（次回期限を計算）
- 買い物の必要フラグ切り替え、商品追加・編集
- 管理者による家族Googleアカウントの追加・削除

## スケジュール画面の表示ルール（2026-10-09）
- 見出し「スケジュール」をタップすると、PWAでもページ全体を再読み込みできます。
- 日付は平日が黒、土曜が青、日曜・祝日が赤。祝日は内閣府公表の2026年・2027年の一覧で自動表示（振替休日と国民の休日を含む）。次年以降の祝日は内閣府の確定公表後に一覧を更新する必要があります。DBへの祝日フィールド追加は不要です。
- 今日・明日は「予定→給食→ゴミ→掃除→買い物」の順（明日は掃除・買い物なし）。予定がない日は「予定なし」、給食・ゴミが未登録なら行ごと非表示。
- 掃除の期限は対象の全件を1件ずつ改行して表示。明後日以降は予定または祝日がある日のみ表示し、長文も省略しません。

## 「やること」タブ（2026-10-09）
- 「スケジュール」「やること」「設定」の3タブ。掃除と買い物は「やること」の下段ブロックに統合。
- 「やること」上段では、通常タスク・買い物が必要な商品・期限を迎えた掃除をまとめて表示。チェックによる動作はそれぞれ異なる（タスク完了／購入済みに変更／掃除完了＋次回期限計算）。
- 新設した tasks テーブルは、名前、担当者（未指定可）、任意の日付、完了状態を保持し、既存の family_members に基づくRLSで保護。完了済みタスクは折りたたんで表示し、再度未完了に戻せる。
- 買い物のカテゴリは「食品」（初期表示）・「雑貨」・「育児」、さらに既存商品のカテゴリも切替可能。カテゴリごとの買い物欄ではチェック＝購入が必要、上段のやること欄ではチェック＝購入完了。

## スケジュールの「やること」統合と天気更新（2026-10-09）
- 今日・明日は、予定、給食、やること、（今日だけ）買い物の順。ゴミ・期限が来た掃除・未完了タスクを「やること」に1件ずつ表示。
- タスクは担当があれば「(パパ)」等を末尾につける。掃除は元データを変えず表示だけ「掃除」を末尾につけ、例として「お風呂掃除」「窓掃除」とする。
- 日付のないタスクと期限切れタスク、期限未設定の掃除は今日へ表示。明日以降のタスク・掃除は各予定日に表示。買い物は今日の要約のみ。
- 天気のCronは `family-weather-four-times-jst`。ジョブの時刻はUTCで `0 2,8,14,20 * * *`（日本時間5・11・17・23時）。古い一日一回のジョブは停止済み。

## 2026-10-09 スケジュール表示の見直し
- 今日のカードは「予定→給食→ゴミ→掃除→タスク→買い物」の順。未登録・該当なしの項目は表示しない（予定は「予定なし」と表示）。ゴミは改行ごと、期限到来の掃除・未完了タスク・必要な買い物は各1行ずつ表示。
- タスクの担当者名は末尾に括弧で追加し、掃除には表示上の接尾辞「掃除」を追加する。商品は必要なものを省略せずに1件ずつ、数量がある場合は数量も表示。
- 明日は「予定→給食→ゴミ」だけ表示し、掃除・タスク・買い物は出さない。明後日以降は、家族の予定が登録された日のみ表示し、ゴミ・掃除・タスクなどの「やること」は表示しない。祝日は予定のある日の日付に表示する。

## 2026-10-09 予定欄のインデント統一
- 今日・明日は見出し「予定」を表示せず、登録済みのカイ・パパ・ママ・イベントを個別に表示する。
- 本文の開始位置は給食・ゴミ・掃除・タスク・買い物、および明後日以降の人物別予定と揃える。
- 予定が1件もない日は従来どおり「予定なし」。明後日以降の予定表示仕様は変更しない。

## 自動Web Push通知（2026-10-13）
- `supabase/functions/family-push` をSupabaseにデプロイ。Web Pushの鍵はサーバーで生成・管理し、公開側には公開鍵のみを渡す。
- 家族が「設定 → プッシュ通知の受信」で端末を登録できる（本人の端末だけRLSアクセス可）。管理者は「サーバーからテスト送信」で自分の端末に本物のWeb Pushを送信可能。
- 管理者が「自動配信を開始」を押すと、`family-push-dynamic-jst` が毎分照合する保存済み日本時間に配信。初期状態は停止、現時点では家族への自動配信は未開始。
- 対象は登録済み・通知許可済み・現在も有効な家族の端末。毎日1回の重複配信防止ログを保持。
- 受信操作・手動テスト・切替手順は [PUSH_NOTIFICATIONS_SETUP.md](PUSH_NOTIFICATIONS_SETUP.md) に記載。既存ショートカットは動作を確認してから停止する。

## 予定ごとのHPリンク（2026-10-13）

- カイ・パパ・ママ・イベントの各予定に、それぞれ独立した任意のホームページURL（`kai_url` / `papa_url` / `mama_url` / `event_url`）を保存できる。既存の `daily` データ73行は変更なし。
- 表示：今日・明日・今後の予定で、**リンクが設定された予定の文章の末尾にだけ**小さな ↗ アイコンを置く。URL未設定の予定は表示・行の高さがこれまでどおり。URLだけがある場合はアイコンを表示しない。
- アイコンのタップは外部Webページを開く（別タブ／ブラウザ、`target=_blank` と `rel=noopener noreferrer`）。予定本文をタップして勝手に外部サイトを開く動作は入れず、誤操作を防止。
- 入力：日付タップによる「その日の予定を編集」画面の末尾、または「月間編集」で日付を開き、「🔗 HPリンクを設定（任意）」を展開。URLを貼り付けて保存。既存リンクがある日は最初から展開される。
- ドメインだけの入力は自動的に `https://` を補う。リンクとして開けるのは `http:` と `https:` のみ。URLはHTMLエスケープし、`javascript:` / `data:` などは保存・リンク表示を禁止。
- データへのアクセスはこれまでのGoogle認証と `daily` テーブルのRLSに従う。通知配信・買い物リストには影響しない。
- 実装を小さく保つため、1つの欄に複数行の予定がある場合でもURLは各欄につき1件。必要に応じて後から個別イベント機能を設計する。
